# 전투 액션 HUD 상태 연동

Presenter는 매 프레임 후반(`PostUpdateWork`)에 가드·닷지·카운터 러시·처형 상태를 조회한다.
게임플레이 판정 규칙을 중복 구현하거나 체력 셀을 갱신하지 않고,
애니메이션의 행동 중단 허용 구간, 가드 오버레이 변화, 처형 거리·방향 조건을 확인한다.
변경된 액션 상태 스냅샷만 위젯에 전달하며, 플레이어 제어가 해제되면 주기적 조회를 중단한다.

- 가드: 사용 가능 여부는 액션 판정 파이프라인으로 확인한다. 활성 표시는
  가드 진입 액션이 끝난 뒤에도 유지될 수 있는 방어 자세를 기준으로 한다.
  패링 판정 구간이 열렸다는 사실을 패링 성공으로 취급하지 않는다.
- 패링: 피격 대상 측에서 확정된 패링 결과를 받으면 게임 시간 기준 0.25초 동안
  금색으로 강조한다. 결과 일련번호로 중복 처리를 방지하며, 사망하거나 Pawn이 교체되면 초기화한다.
- 닷지: 사용 가능 여부는 실제 실행과 동일한 액션·오버레이·행동 중단 판정으로 확인한다.
  활성 표시는 닷지 액션이 실행 중이라는 의미이며, 공격을 회피했다는 의미는 아니다.
- 처형: 사용 가능 표시에는 컨트롤러의 타깃 락 정책과 협업 사전 검사가 필요하다.
  사전 검사는 시전자·대상 상태, 처형 기회, 거리, 방향, 준비된 실행 데이터,
  실행 허용 판정, 피해 적용 가능 여부를 확인한다. 진행 중 표시는 시전자 애니메이션만이 아니라
  시전자 역할의 협업 세션을 기준으로 한다. 실제 입력 시에는 예약·실행 전에 다시 검증한다.
- 카운터 러시: 준비된 실행 데이터와 실제 실행 평가 경로로 사용 가능 여부를 조회하고, 실행 중이면 Active로 표시한다. 조회만으로 반격 기회를 소비하지 않는다.
- 퍼펙트 닷지: DefenseComponent의 실제 퍼펙트 닷지 실행 상태를 전달한다. 일반 닷지 실행 중 표시와 회피 성공 결과를 구분한다.
- 별도 일반 돌진 표시와 GuardBreak 아이콘은 카운터 러시 연동 완료에 포함하지 않는다. 실제 시스템에 없는 가드브레이크 쿨타임을 표시하지 않는다.

조회에는 준비된 런타임 맵을 사용한다. `BuildOverlaySnapshot`은 필요 시 정책 레지스트리를 갱신한 뒤 각 정책의 현재 상태를 수집한다. 게임플레이 실행 부작용을 만들지 않는다는 뜻이며 내부 캐시 갱신까지 금지하는 순수 함수라는 뜻은 아니다.
조회 과정에서 실행 객체 생성, 가드 입력 의도 변경, 처형 기회 예약, 액터 회전,
몽타주 재생을 수행하지 않는다. 필요한 데이터나 실행 객체가 준비되지 않았으면 사용 불가로 판단한다.
사전 검사가 이후 애니메이션 재생 성공까지 보장하지는 않으며,
실제 런타임의 실행 실패 및 정리 처리가 최종 기준이다.

표시 색상은 사용 불가 시 어두운 회색, 사용 가능 시 미색, 실행 중일 때 청록색이다.
패링 성공은 금색으로 강조한다. 처형 준비는 종류와 무관하게 미색이며, 비즉사는 기존 검/충격 아이콘,
즉사는 해골 아이콘으로 구분한다. 확대·점멸 효과는 사용하지 않는다.
종류는 기존 처형 사전 검사 결과를 전달하며, 실행 중에는 세션에서 확정한 종류를 유지한다.
HUD 클래스 기본값의 `Combat HUD|Style`에서 `ExecutionIcon`과 `LethalExecutionIcon`을 교체할 수 있다.
즉사 텍스처 미지정 시 기존 아이콘으로 대체하고, 사용 불가 상태에서는 기존 아이콘을 표시한다.

## 즉사 체력 강조

적 체력바의 남은 HP 칸만 즉사 체력 조건에서 붉게 표시한다. HUD에 별도 체력 임계값은 두지 않고
대상의 `CExecutionCollaborationComponent::IsInLethalExecutionHealthRange()`로 기존 판정을 재사용한다.
이 표시는 거리·방향·밸런스 기회·실행 데이터 준비 여부를 보장하지 않는다. 실제 실행 가능 표시는
처형 아이콘이 담당한다. 즉사가 비활성화된 대상에는 저체력만으로 강조하지 않는다.

대상 측 처형 세션이 활성화되어 있으면 세션에 확정된 종류를 사용한다. 비즉사처형 피해로
임계값을 통과해도 실행 도중 즉사 표시로 바뀌지 않는다. 종료·취소 후에는 체력 조건을 다시 읽는다.
사망 시 기존 규칙대로 대상 패널을 숨긴다.

HUD 위젯 클래스 기본값 `Combat HUD > Style > Lethal Health`:

- `Enable Lethal Health Tint`: 강조 사용 여부 (기본 true)
- `Lethal Health Tint`: 강조 색상 (기본 linear RGBA 0.8, 0.18, 0.16, 1)
- `Lethal Health Tint Blend Time`: 전환 시간 (기본 0.15초, 0이면 즉시 변경)

UMG NativeTick의 델타 시간으로 smoothstep 보간한다. 전환 중 반전은 현재 표시 색상에서 시작한다.
체력 이벤트가 반복되어도 보간을 재시작하지 않는다. 새 대상·HUD 재구성은 해당 대상의 색상으로
즉시 초기화하며, 타깃 해제·플레이어 교체 시 이전 보간은 폐기한다.
플레이어 HP, 빈 칸 배경, 실드, 밸런스, 수치 텍스트 및 처형 아이콘 색상은 변경하지 않는다.

### G4 분리 검증 (2026-10-22)

기준은 D1·P2-A·G3가 머지된 main `1e02c8a5`이다. 기본 Unity
PortfolioEditor Win64 Development 빌드와 전체 자동화 93개가 통과했다
(성공 91, 기존 경고 동반 성공 2, 실패·미실행 0). 이 중
`Portfolio.UI.CombatHUD.` 15개가 처형 사전 조회, 아이콘 fallback,
체력 임계값·회복·정책 비활성, 세션 종류 유지, 타깃 교체·사망,
보간 반전·반복 갱신·재구성을 검증한다.

실제 SciFiMap PIE에서 health hint, 일반 처형 완료·중단, 즉사 처형 완료·중단,
처형 중 플레이어 사망의 6개 시나리오를 실행했다. 실제 controller HUD,
판정 조회, paired execution 요청, 원래 몽타주와 commit notify를 사용했다.
일반 처형의 피해와 생존, 즉사 처형의 사망 및 패널 정리, 중단 시 양측 세션과
HUD active 해제를 확인했다. Slate UI를 포함한 화면에서 일반/즉사 아이콘,
미색 준비·청록 실행, 남은 HP의 적색 강조를 확인했다.

처형 기회 준비에는 임시 대상의 승인된 Parry 결과를 주입했다. 자연 입력으로
패링 성공까지 검증한 결과는 아니다. health hint의 직접 TryKill은 HP/패널 정리
검사용이며, 해당 경로에서 기존 DeadInStartFailed fallback 기록이 발생했다.
일반 사망 애니메이션 전체 검증을 의미하지 않는다. 실제 즉사 처형 경로는 별도로
완료·중단을 검증했다. 임시 계측과 Slate 의존성은 최종 변경에서 제거했다.
기존 맵·BP·몽타주·AI 튜닝은 저장하거나 변경하지 않았다.

### C1–C4 누적 경계 검증 (2026-10-22)

아직 커밋하지 않은 상태에서 공유 파일의 변경 부분을 나눠 아래 누적 상태를
실제로 구성했다. 각 경계에서 기본 Unity (`-DisableAdaptiveUnity`) Editor 빌드,
전체 `Portfolio.` 자동화, `CDodgeAssets -Verify`, `CExecutionMontageAudit`를 실행했다.

| 경계 | 추가 범위 | 누적 파일 | 자동화 |
| --- | --- | ---: | ---: |
| C1 | 처형 종류 조회 + 기존 사전 조회 테스트 확장 | 3 | 90개 통과 |
| C2 | 일반/즉사 아이콘 + 텍스처/PNG + 표시 테스트 | 11 | 91개 통과 |
| C3 | 즉사 체력 힌트/보간/생명주기 + 테스트 | 12 | 93개 통과 |
| C4 | HUD 동작·아이콘·검증 범위 문서 | 14 | 93개 통과 |

네 경계 모두 빌드 성공, 에셋 검사 오류 0, 자동화 실패·미실행 0이다.
각 실행의 경고 동반 성공 2개는 기존 StartNotifyDelivery의 legacy 머티리얼 참조와
TimeEffects.ValidationAndCleanup의 world cleanup이다. C2부터 신규 아이콘 로드와
fallback 검사가 포함되고, C3부터 체력 힌트·보간 검사 2개가 추가된다.

최종 런타임으로 위 실제 PIE 6개 조건을 다시 실행해 동작 99개와 캡처 34개 판정을
통과했다(UI 포함 PNG 17장). 임시 계측 제거 후 기본 Unity 빌드와 전체 93개도
다시 통과했다. 코드·에셋은 이전 통합 검증본과 바이트가 동일하며 구현 수정은 없었다.
이 결과 문단은 실행 완료 후 문서만 갱신했으므로 C4 빌드 당시 문서와 내용 차이가 있다.
기존 에셋과 원본 작업 폴더, 104개 변경 보존본은 유지했다.

실제 시스템에 없는 쿨타임 링이나 리소스 비용은 표시하지 않는다.

검증을 위해 `Portfolio.UI.CombatHUD`에 액션 사용 가능 여부·취소 허용 구간,
처형 거리·방향·기회·읽기 전용 조회, Presenter의 패링·수명 관리,
위젯 색상 테스트를 추가했다. 테스트용 구성은 런타임 판정을 분리해 확인한다.
에디터 플레이에서는 프로젝트의 실제 몽타주, 행동 중단 허용 노티파이,
일반·치명 처형 쌍을 추가로 확인해야 한다.

2026-09-20 마감 검토에서 HUD 12개와 Balance 2개 테스트가 모두 통과했다. 사용자 PIE 확인도 완료했으며 개별 몽타주 조합을 모두 검증했다고 확대하지 않는다. 최종 범위는 [브랜치 마감 기록](../../Docs/07_Portfolio_Documents/Portfolio_Production/34_Gameplay_Combat_HUD_Branch_Closure.md)을 따른다.
