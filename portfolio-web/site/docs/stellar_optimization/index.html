측정 목적과 판단 기준

다수 AI가 함께 존재할 때 비용이 증가하는 원인을 인지·이동·애니메이션·BT 갱신·전투 처리로 나누어 살펴봤습니다. 처리 횟수를 줄였다는 사실, 전체 프레임 시간이 낮아졌다는 관측, 게임 동작을 유지한 채 적용할 수 있다는 판단을 구분했습니다.

분류확인한 내용해석
참여 상한 비교AI 수를 유지하고 경계 참여 상한만 변경동시 행동량을 제한하는 정책의 비용 비교
갱신 주기 조정서비스·파라미터 갱신 횟수와 동작 관찰호출 감소를 전체 성능 개선으로 확대하지 않음
기능 비활성화이동·메시·무기·전투 처리 등을 분리병목 후보를 찾는 진단 실험. 완성된 최적화와 구분

기존 인지 개선의 10월 반복 검증은 별도 사례입니다. 아래 7월 실험과 조건·횟수가 다르므로 수치를 합산하거나 같은 검증으로 묶지 않습니다.

경계 참여 상한: 이동 비용과 Frame p95 비교

2026년 7월 10일, 40·80마리 각각에서 Alert 상한 6과 40을 비교했습니다. Engage 상한은 2로 유지했습니다. AI를 제거하거나 Tick을 끈 비교가 아니라, 같은 개체 수에서 경계 이동에 참여할 수 있는 수를 바꾼 실험입니다.

조건별 1회, 총 4개 캡처의 과거 비교입니다. 캡처는 약 36.6~37.1초이며 당시 분석 구간은 약 30.6~31.1초입니다. 로그에 최종 역할 배정 요약이 없어 실제 배정 인원을 확정하지 못했습니다. 표의 6·40은 설정한 상한이며, 현재 빌드의 성능이나 반복 측정 재현성을 보장하는 수치가 아닙니다.

측정값과 원본 연결

표와 PPT는 당시 보고값을 유지합니다. 아래 숫자 열 발췌는 원본 CSV에서 FrameTime·GameThreadTime·CharacterMovement만 추출했습니다. 첫·마지막 3초를 제외한 선형 보간 p95 재계산은 원 보고값과 수천분의 1ms 수준의 차이가 있으며, 재집계 값으로 과거 기록을 덮어쓰지 않았습니다.

BT 갱신: 작업량 감소와 행동 안정성

주기를 늦추면 호출 수는 줄지만, 대상 정보 생산과 역할 유지에 필요한 갱신까지 늦추면 행동이 달라집니다. 따라서 서비스마다 책임을 나누고, 호출 감소량만으로 적용 여부를 판단하지 않았습니다.
