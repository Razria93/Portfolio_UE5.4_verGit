30: ## 제어 CVar
31: 
32: ```text
33: Portfolio.AI.RuntimeLOD.EnemyActorTickMode
34: ```
35: 
36: | Mode | 이름 | 제어 내용 | 목적 |
37: | ---: | --- | --- | --- |
38: | 0 | Default | 기본 tick 유지 | baseline |
39: | 1 | EnemyActorTickDisabled | `ACEnemy::Tick` 비활성화 | Enemy actor-level polling tick 비용 분리 |
40: 
41: 현재 구현 범위는 Mode 1까지다.
42: 
43: 주의:
44: 
45: - Mode 1은 `ACEnemy::Tick` 자체를 끄므로 PIE 중 CVar를 1에서 0으로 되돌리는 runtime restore 검증에는 적합하지 않다.
46: - 정규 측정은 PIE 시작 전 CVar를 설정한 뒤 진행한다.
47: - Mode 1은 `CActionComponent`, `CMovementComponent`, `CharacterMovementComponent`, `BehaviorTreeComponent`, `SkeletalMeshComponent` tick을 끄지 않는다.
48: - 측정 명칭, CVar, 전용 측정 맵 에셋명을 `EnemyActorTick` 기준으로 정리했다.

135: ## 해석
136: 
137: `EnemyActorTickMode 1`은 기능적으로 성공했다.
138: 
139: ```text
140: Mode 0: Ticks/CEnemy = 40 또는 80
141: Mode 1: Ticks/CEnemy = missing
142: ```
143: 
144: 하지만 성능 병목으로 보기는 어렵다.
145: 
146: ```text
147: BT Tick은 반복 측정에서 비교적 안정적이다.
148: Frame / GameThread 변동은 CharacterMovement와 Animation 변동을 더 크게 따라간다.
149: TickActors p95 감소폭은 작고, Frame / Game p95 개선으로 안정적으로 이어지지 않는다.
150: ```
151: 
152: 즉 이번 측정의 결론은 다음과 같다.
153: 
154: ```text
155: ACEnemy actor tick 제거는 제거 가능한 polling tick 검증으로는 의미가 있다.
156: 하지만 현재 Runtime LOD 성능 병목의 본체는 아니다.
157: 후속 분석은 Movement와 Animation을 독립적으로 통제하는 환경에서 진행해야 한다.
