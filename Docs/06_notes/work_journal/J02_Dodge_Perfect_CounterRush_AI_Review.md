## 1. 사용자의 요청사항

최초 요청은 Hit 탈출용 Dodge를 사전 방어로 전환하고, 유효 공격 접촉으로 저스트 회피를 판정한 뒤 추가 공격 입력으로 재접근과 단발 공격을 연결하는 것이었다. BU·연속 카운터 콤보는 제외했다. 영상은 동작과 시각 연출의 기준이지 내부 판정의 증거가 아니었다.

최초부터 무적·슬로우·몸 효과·화면 효과·반격 기회·러시 효과의 수명 분리, 슬로우 수치 튜닝, 중단 정리, 실제 코드와 에셋 검증이 요구됐다. 이후 사용자는 전용 모션 복제본의 루트 고정과 충돌 적용 이동을 승인했다.

아래는 실제 코드에서 확인한 구현 명세다. 구현자의 당시 심리나 기록되지 않은 선택 이유를 사실로 추정하지 않는다.

러시는 루트 고정 복제 모션과 RootMotionSource 이동을 분리했다. HUD는 기회를 소비하지 않는 조회를 사용한다. 성공 효과는 실행 무적과 별도 타이머를 갖지만, 몸/무기의 독립된 강화 표현과 디자이너가 애니메이션에서 연출을 편집하는 구조까지 제공한 것은 아니다.

## 3. 사용자 검토 내용

- 사용자는 이동과 공격을 분리한 카운터 구조를 긍정적으로 평가했고 유지하기로 했다.
- 초기 몸 발광의 모양·재질·강도 변화가 의도한 표현과 달랐다. 모듈형 캐릭터 파츠 대응도 필요했다.
- 무기의 붉은 표현은 몸과 수명이 달라야 했으나 초기 구현에 없었다.
- 수치 노출만으로 원하는 디자인 제어가 충족되지는 않았다. 시작 이벤트 위치, 보간, 종료 기준을 조절할 필요가 있었다.
- 고정 중심 거리 대신 캐릭터 크기를 반영한 간격과 실제 이동을 관찰할 디버그가 필요했다.

이 사례의 차이는 세 종류다: (1) 기존 요구의 시각적 충족 부족, (2) 초기 구현의 임시 정책, (3) 검토 과정에서 추가로 구체화된 요구. 모든 차이를 최초 요구 누락이나 단순 추가 요청 중 하나로만 분류하지 않는다.

## 4. 합의 결과와 이유 — 아직 미구현

| ID | 합의/후속 방향 | 수용 기준 |
| --- | --- | --- |
| D01 | 현행 접촉 판정 및 별도 Reaction 유지 | 기존 판정·기회 소비·무적 회귀 테스트 유지 |
| D02 | 파츠형 메시 우선, 지정 파츠에 백업 프레넬 적용 | 점진 발광 후 리액션 종료 즈음 원색 복귀. 접합부·헤어·LOD 직접 확인 |
| D03 | 준비부터 공격까지 무기 발광. 미사용 만료/취소 시 감소, 사용 시 러시로 수명 인계 후 타격 구간 종료 시 감소 | 러시 시작의 기회 소비로 효과가 먼저 꺼지지 않음. 빗나감도 구간 종료 기준. 교체·사망·중단 시 원래 무기 정리 |

| D05 | 기존 VignetteIntensity 보간 우선 | 이전 상태로 부드럽게 복원, 반복 실행 시 튐 방지. 비대칭 PP는 범위 제외 |
| D06 | 스케일 반영 캡슐 반경 합 + 여유 거리, 기존 최대 거리·충돌 유지 | 근접 시 역방향 이동 없음. 예정/실제 이동과 충돌 종료를 디버그로 비교 |
| D07 | 이동 상태에 맞춘 FOV·리본/입자 우선, 몸 잔상 비용 검토 | 이동 0·벽 막힘 시 과장된 연출 방지. 커스텀 PP는 후순위 |

프레넬은 파츠 경계 검출이 아니라 표면 노멀/시선 기반이다. 파츠 분리 자체가 접합선 발광을 보장하지 않으며 통합 메시도 자동 해결책은 아니다. 백업에서 확인한 핵심 에셋은 `M_Fresnel_D`와 `MI_Fresnel` 머티리얼이다. 별도 Niagara 구성, 세부 파라미터와 실제 모양은 에디터 확인이 남아 있다.

적/무기의 디졸브에서 C++의 시작·강도·종료 전달과 BP의 MID/Timeline 표현 분리를 참고하되, 디졸브 이벤트를 발광에 재사용하지 않는다. 종료된 옛 실행이 새 효과를 지우지 않도록 소유권을 구분한다.

### 블링크 확장 메모

블링크는 카운터 러시와 별도 실행 객체로 구성한다. 러시는 접근 방향에서 앞 간격을 확보하고, 블링크는 적 전방 벡터 기준 뒤쪽 후보를 계산한다. 반경/여유 거리 계산과 디버그는 공통화 후보지만, 목적지 점유·벽·바닥·실패 처리 및 순간이동 정책은 별도 책임이다. 이번에 러시에 블링크 옵션을 넣거나 실행을 구현하지 않는다.

## 5. 최종 결과물

**연출 개선 결과: 미완료 / 후속 구현 대기.** 이번 산출물은 초기 구현을 재검토할 수 있는 코드·에셋·문서 기준점이다. 개선 전 영상을 촬영하지 않은 상태이며, 자동 테스트 통과를 시각적 승인으로 표현하지 않는다.

향후 이 절에 개선 태그/SHA, D01~D07 구현 근거, 전후 영상 타임코드, 수동 검증 결과 및 사용자 승인/잔여 문제를 추가한다. 과거 기준점은 이동하거나 수정하지 않는다.

## 6. 협업 과정에서 얻은 개선점

기능적 성공 조건과 시각적 성공 조건을 별도로 정의해야 한다. 표현 구현 전에는 시작 트리거, 적용 대상, 시간 기준, 보간, 종료 사유, 편집 위치, 중첩/취소 정책을 사용자와 확인한다. 작은 PIE 시각 검토를 초기 단계에 배치하고, 자동 테스트로 검증 가능한 전투 규칙과 사람이 확인해야 하는 체감을 분리한다.
