# 일반 회피 · 저스트 회피 · 카운터 러시 구현 및 검증 노트

> 2026-09-22: `dodge-review-01`은 초기 구현의 1차 사용자 검토 기준점이다. 연출 개선 완료본이 아니다. [협업 검토](work_journal/J02_Dodge_Perfect_CounterRush_AI_Review.md)와 [이번 검증·촬영 준비 기록](work_journal/evidence/Dodge_Review_01_Baseline.md)을 함께 본다. 아래 2026-09-21 검증 표는 당시 기록으로 유지한다.

## 1) 목적과 범위

기존 Hit 탈출용 Dodge를 공격 접촉 전에 시작하는 방어 행동으로 바꾸고, 타이밍 성공을 별도 PerfectDodge 리액션과 추가 입력 CounterRush로 연결한다. 참고 영상의 내부 구현을 추정하여 복제하는 것이 아니라 프로젝트의 판정·실행·종료 규칙을 명시한다.

- 일반 회피와 저스트 회피는 기본 플레이어와 Stellar 플레이어에 연결한다.
- CounterRush는 호환 공격 애니메이션이 확보된 Stellar 플레이어에 우선 연결한다. 기본 플레이어에는 러시 데이터를 임의로 연결하지 않는다.
- 러시는 한 번의 유한한 돌진과 단일 공격이다. BU 보유 조건·소모, 카운터 콤보, 적 회피 AI는 이번 범위에서 제외한다.
- 회피 방향은 기존 단일 방향을 유지한다. 8방향 회피, 지속 타깃 추적, 러시 무적은 추가하지 않는다.
- 원본 애니메이션은 유지하고 러시 전용 복제본에서 루트를 고정한다.

## 2) 전투 흐름과 선택한 규칙

```text
회피 입력 → 일반 Dodge 실행
  ├─ 무적 구간 밖 접촉 → 기존 피격 처리
  ├─ 무적 구간 중 저스트 구간 밖 접촉 → 일반 회피 성공
  └─ 저스트 구간의 유효 접촉 → PerfectDodge 판정 (실행당 1회)
       → 일반 Dodge 중단 → 별도 PerfectDodge 리액션
       → 성공 연출 + 성공시킨 공격자를 대상으로 카운터 기회 부여
       ├─ 추가 공격 입력 없음 → 완료 후 유예 시간 만료
       └─ 연결 가능 시점 이후 추가 공격 입력 → CounterRush → 단일 공격 → 종료
```

- Hit 리액션 중 Dodge로 탈출하지 않는다. 회피는 피격 전에 시작해야 한다.
- 저스트 판정은 회피 버튼을 눌렀다는 사실만으로 성공하지 않는다. 회피 실행 중 실제 유효 공격 접촉이 있어야 한다.
- 일반 무적과 저스트 창은 시작 포함·끝 제외 구간이다. 저스트 창은 일반 무적 창과 겹치는 범위에서만 유효하다.
- `FDamageSpec`의 `bCanGuard`, `bCanParry`, `bCanDodge`를 각각 적용한다. 가드·패링 불가이면서 회피 가능한 공격을 별도로 구성할 수 있다.
- PerfectDodge도 `bCanDodge=false` 공격까지 막는 절대 무적이 아니다. 회피 가능한 공격에 대해 실제 리액션 실행 동안 보호한다.
- 회피 성공 접촉은 HP 피해·일반 Hit 리액션·넉백을 발생시키지 않는다. 피해 수치 0과 접촉 미수락을 구분하여 같은 타격 창의 중복 접촉을 막는다.
- PerfectDodge 중 후속 회피 가능 접촉은 일반 Dodge 결과로 처리한다. 저스트 리액션·슬로우·카운터 기회를 다시 시작하지 않는다.
- 저스트 리액션은 별도 몽타주를 사용한다. 현재는 기존 회피 모션을 복제한 임시 표현이며 최종 전용 모션이 아니다.
- 카운터는 자동 연결하지 않는다. 조건을 만족하는 추가 공격 입력에서 러시를 선택한다. 일반 공격 입력과 같은 입력 경로를 이용하며 별도 홀드 요구는 없다.
- 카운터 대상은 저스트 성공을 발생시킨 공격자다. 현재 락온 대상으로 바꾸지 않는다.
- 러시 시작 시 대상 위치를 읽고 방향·거리를 확정한다. 이동 중 대상이 움직여도 추적하지 않으며 CharacterMovement 충돌을 따른다.
- 카운터 기회는 러시 시작 및 이동 준비가 성공한 뒤 한 번 소비한다. 준비 실패를 성공으로 간주하여 미리 소모하지 않는다.

## 4) 임시 튜닝과 시간 기준

아래 값은 초기 구현값이다. 참고 이미지에서 정확한 프레임·배율을 역산한 값이 아니며 PIE에서 체감 및 애니메이션 접촉을 확인한 뒤 조정한다.

| 항목 | 초기값 | 기준 |
| --- | --- | --- |
| 일반 회피 무적 | `[0.0, 0.5)`초 | 일반 Dodge 몽타주 위치 |
| 저스트 회피 판정 창 | `[0.0, 0.18)`초 | 일반 Dodge 몽타주 위치, 일반 무적 창과 교집합 |
| 러시 연결 가능 시작 | `0.45`초 | PerfectDodge 몽타주 위치 |
| 완료 후 러시 유예 | `0.4`초 | `FPlatformTime` 실제 경과 시간 |
| 러시 대상 허용 거리 | `600`cm | 현재 플레이어와 성공 공격자 사이 거리 |
| 러시 이동 시간 | `0.25`초 | CharacterMovement의 RootMotionSource 진행 시간 |
| 러시 최대 이동 거리 | `450`cm | 시작 시 확정, 충돌로 실제 거리가 줄어들 수 있음 |
| 러시 목표 정지 간격 | `120`cm | 시작 시 대상 거리에서 제외 |
| 성공 슬로우 | 배율 `0.15`, `0.22`초 | 플레이어와 성공 공격자만, 실제 경과 시간 |
| 붉은 몸체 오버레이 | `0.7`초 | 실제 경과 시간 |
| 로컬 비네트 | 강도 `0.85`, `0.4`초 | 실제 경과 시간 |
| 러시 기본 피해 | `20` | Sword / CounterRush / 0 DamageSpec |

몽타주 위치 구간은 재생 속도가 바뀌어도 같은 애니메이션 위치를 가리킨다. 따라서 화면에서 체감하는 실제 지속 시간은 슬로우 및 PlayRate에 따라 달라진다. 러시 이동은 실제 시간 타이머가 아니므로 시간 배율과 몽타주 재생을 함께 확인해야 한다.

성공 슬로우·화면 연출·카운터 유예는 실제 시간 기준으로 만료된다. 일시정지 중에도 실제 시간 자체는 진행되므로 재개 후 다음 갱신에서 만료될 수 있다. 기존 HitStop은 월드 게임 시간 기준을 유지한다.

같은 액터에 시간 효과가 겹치면 저장한 기준 배율과 남아 있는 효과 배율 중 최솟값을 적용한다. 각 효과는 독립적으로 만료되며 한 효과의 종료가 다른 효과를 먼저 해제하지 않는다. 모두 종료되면 처음 저장한 배율로 복원한다. 이는 슬로우 배율을 서로 곱하는 방식이 아니다.

## 5) 애셋과 데이터

### 편집 가능 범위와 현재 제약

- `CDefenseTuningTypes.h`의 회피 창·연결 시점·유예·대상 거리는 `EditAnywhere` 데이터다. 애니메이션 Notify 트랙에서 판정 창을 편집하는 구현과는 다르다.
- `CReactionFeedbackComponent.h`의 슬로우 배율/시간, 몸/화면 지속 시간, 몸 재질은 `EditAnywhere`다. 모든 값이 하드코딩된 것은 아니다. `PlayPerfectDodgeSuccess`의 비네트 강도 `0.85`와 대표 `GetMesh()` 적용, 성공 시작 트리거는 코드에 고정되어 있다. 페이드 Curve나 무기 발광 채널은 없다.
- `CAction_CounterRush.h`의 `RushDuration`, `MaxTravelDistance`, `StopDistance`는 `EditDefaultsOnly`다. 현재 BP 데이터는 native 실행 클래스를 참조하므로 플레이어 BP의 액션 행에서 즉시 해당 값을 편집하는 구조라고 설명해서는 안 된다. 실제 편집 경로 개선은 후속 범위다.
- `CAction_CounterRush::CommitStarted`는 수평 거리에서 중심 간 `StopDistance`를 빼고 최대 거리를 적용한다. 캡슐 반경 합 기반 간격은 아직 구현되지 않았다.
- `CDodgeAssetsCommandlet`의 초기 재질 그래프/색/완료 및 충돌 통지 배치는 제작 시 코드 상수다. 저장 후 에셋에서 수정할 수 있으나 기존 에셋을 완전히 재설정하는 도구는 아니다.
- 신규 Lucy 회피 시퀀스 두 개는 후보 자료로 별도 보존한다. 현행 몽타주 교체나 시각적 승인을 의미하지 않는다.

저스트 리액션은 `Global / PerfectDodge` 데이터로 선택하며 완료 통지를 `1.3`초에 배치한다. 러시 몽타주의 초기 통지 배치는 HitContext `0.27~0.8`초, Collision `0.3~0.7`초, CompleteAction `1.5`초다. 모두 몽타주 시간이며 실제 검날 접촉과의 일치는 시각 검증 대상이다.

러시 접근·타격 트레일은 `0.02~0.75`초의 ActionFeedback 창으로 연결한다. 별도 카운터 콤보 연출은 없으며 실제 적중 피드백은 기존 HitFeedback 경로를 사용한다. 전용 러시 시퀀스의 Notify는 비우고 위 몽타주에서만 게임플레이 창을 소유한다. 원본 Sprint 시퀀스는 변경하지 않는다.

`CDodgeAssets`는 `-Apply`에서 없는 전용 애셋·데이터를 생성하고, 인자 없는 실행에서는 저장된 참조를 확인한다. 기존 전용 애셋이 있을 때 모든 설정을 초기값으로 덮어쓰는 재생성 도구는 아니다. 이후 수동 튜닝 값을 바꿀 경우 해당 애셋을 직접 검토한다.

## 6) 실패·중단·정리 규칙

- 시작 실패 또는 이미 중단된 몽타주에는 회피 보호를 남기지 않는다. 이전 실행의 종료 요청이 새 실행을 지우지 않도록 세대를 구분한다.
- PerfectDodge 재생 시작에 실패하더라도 이미 수락한 성공 접촉을 나중에 피해로 되돌리지 않는다. 대신 실제 리액션 보호와 새 카운터 기회는 부여하지 않는다.
- PerfectDodge 정상 완료에는 러시 유예를 남긴다. 일반적인 중단에는 기회를 정리한다. 러시 전환 도중 시작 실패는 전환용 유예 안에서 재시도 가능하도록 처리한다.
- 플레이어 사망·참조 재초기화·EndPlay에서는 회피 및 카운터 상태를 정리한다. 성공 공격자 사망은 카운터 기회를 취소하며 부활로 이전 기회가 돌아오지 않는다.
- 대상 삭제·거리 초과·기회 만료 시 준비 조회는 실패한다. 거리 초과만으로 기회를 소비하지 않으므로 유효 시간 안에 다시 가까워지면 조건이 다시 성립할 수 있다.
- 러시 취소·완료에서는 자신이 등록한 이동 효과를 정리한다. 자연 만료 이후 수평 관성이 돌진을 연장하지 않도록 종료 속도를 제한한다.
- 몸체 오버레이·비네트는 독립 수명으로 복원한다. 정상 리액션 완료가 남은 성공 연출을 즉시 잘라내지는 않는다. 사망·EndPlay·재초기화 정리는 별도로 수행한다.
- 성공 연출 취소는 해당 슬로우 토큰만 취소한다. 다른 HitStop까지 함께 삭제하지 않는다.

## 7) PIE 수동 검증

### 준비

1. 테스트 맵에서 Stellar 플레이어와 타격 가능한 적을 배치한다. 초기에는 평지·단일 적으로 진행한다.
2. 동일 공격의 타격 시점을 재현할 수 있게 설정한다. 경계 확인은 느린 재생이나 프레임 진행을 활용하되 몽타주 위치와 실제 경과 시간을 구분한다.
3. HP, 현재 Action/Reaction, 몽타주 위치, HUD 상태를 함께 확인한다. 화면 이펙트만 보고 판정 성공으로 결론 내리지 않는다.
4. 테스트용 공격 설정을 변경한 경우 종료 후 의도한 기본값으로 되돌린다. 다음 항목은 확인 전까지 모두 미검증이다.

| 시나리오 | 조작 | 기대 결과 |
| --- | --- | --- |
| 사전 방어와 Hit 탈출 제거 | 먼저 피격해 Hit 중 회피 입력, 이후 Idle에서 회피 | Hit 중 탈출하지 않으며 Idle에서는 기존 회피 실행 |
| 일반 무적 경계 | 회피 위치 약 `0.3`초와 `0.5`초 이후에 같은 공격 접촉 | 전자는 피해·Hit·넉백 없음, 후자는 다른 방어가 없으면 정상 피격 |
| 저스트 경계 | 접촉을 `0.18`초 직전과 직후로 이동 | 직전에는 별도 PerfectDodge, 직후에는 일반 회피만 성립 |
| 헛회피 | 적 공격 범위 밖에서 회피 | 저스트 리액션·성공 연출·카운터 기회 없음 |

| 여러 공격자 | 두 적을 겹치거나 번갈아 타격 | 최초 성공 공격자로 기회 고정, 다른 적 접촉이 대상을 바꾸거나 기회를 연장하지 않음 |
| 추가 입력 연결 | 성공 후 `0.45`초 이전/이후에 각각 공격 입력 | 이전에는 러시 실행 안 됨, 이후 조건 충족 시 한 번 실행; 입력 없이 자동 러시 없음 |

| 중복 입력 | 러시 시작과 동시에 공격 연타 | 동일 기회로 러시를 중복 시작하거나 돌진을 누적하지 않음 |

| 락온 독립성 | 적 A로 저스트 성공 후 적 B에 락온 | 러시는 A를 기준으로 준비·방향 확정 |
| 고정 방향 이동 | 러시 시작 직후 대상이 옆으로 이동 | 러시가 계속 추적·회전하지 않음 |
| 벽·경사·모서리 | 벽 앞, 언덕, 캐릭터 밀착 상태에서 러시 | 벽 통과·무한 이동·종료 후 수평 미끄러짐 없음; 지형 결과는 실제 관찰 기록 |
| 러시 피격 | 러시 도중 적의 별도 유효 공격 | 저스트 무적이 러시에 상속되지 않으며 기존 피격 규칙 적용 |
| 단일 타격 | 러시 검이 적에 닿은 상태로 타격 창 유지 | 같은 적에게 한 타격 창당 한 번 피해, 카운터 콤보 자동 시작 없음 |
| 재생 실패 | 테스트 복제 BP에서 Perfect 또는 Rush 몽타주를 비우고 시도 | 남는 무적·이동·활성 HUD 없음; Rush 준비 실패는 성공 소비로 처리하지 않음 |
| 조기 중단·재실행 | 회피/저스트/러시를 중단한 뒤 새 실행 시작 | 이전 종료가 새 실행을 지우지 않으며 이동·충돌 창 잔류 없음 |
| 슬로우 중첩 | 저스트 슬로우 중 다른 HitStop을 발생시키고 순서를 반대로 반복 | 먼저 끝난 효과가 나머지를 해제하지 않고 모두 끝나면 원래 배율 복원 |
| 시각 연출 | 저스트 성공을 정상 속도로 여러 차례 확인 | 붉은 몸체와 화면 외곽 강조가 명확하고 각 수명 후 복원; 다른 적·세계 전체는 느려지지 않음 |
| 사망·리스폰·PIE 종료 | 연출 및 카운터 기회 도중 사망/재생성/PIE 종료 후 재진입 | 시간 배율·오버레이·비네트·기회·이동 상태가 다음 실행에 남지 않음 |
| HUD와 순수 조회 | 성공 후 입력 없이 대기, 일반/저스트/러시 상태 비교 | 조회만으로 기회가 소모되지 않으며 실제 상태와 Ready/Active 일치 |
| 기본 플레이어 회귀 | 기본 BP로 일반·저스트 회피 및 추가 공격 입력 확인 | 호환 스켈레톤으로 회피 실행, 없는 러시가 Ready로 뜨지 않음, 러시 미구현 상태 때문에 일반 입력이 손상되지 않음 |

수동 결과에는 사용 BP·몽타주 PlayRate·시간 배율·적 공격 설정과 재현 방법을 함께 적는다. 특히 전용 복제본의 루트 고정 품질, 검 궤적과 타격 창, 벽에서의 밀착, 카메라 연출은 NullRHI 자동 실행만으로 승인하지 않는다.

## 8) 검증 상태 및 완료 판정

2026-09-21 통합 검증 결과다. 이전 단계의 44개 결과와 구분하여 최신 50개 테스트 및 저장 애셋을 재검증했다.

자동 검증과 수동 검증을 구분한다. 코드·애셋 작성 완료, 빌드 통과, 자동 테스트 통과만으로 모든 Blueprint 콜백 재진입이나 실제 플레이 체감까지 검증했다고 표현하지 않는다.

실제 엔진 몽타주 갱신을 사용한 `AuthoredPlayback`은 원본 기본 Dodge, 전용 기본 PerfectDodge, 전용 Stellar CounterRush의 완료 Notify 및 러시 기회 소비를 확인한다. 테스트는 블렌드 가중치와 Notify 큐를 갱신하지만 전체 AnimBP/렌더링/무기 충돌 장면을 재현하지는 않는다. 벽·경사 이동, 실제 검날 접촉과 연출 품질은 위 PIE 항목으로 남는다.

실행 예시:

```text
Build.bat PortfolioEditor Win64 Development -Project=<Portfolio.uproject> -WaitMutex -NoHotReloadFromIDE
UnrealEditor-Cmd.exe <Portfolio.uproject> -unattended -NullRHI -nosound -ExecCmds="Automation RunTests Portfolio." -TestExit="Automation Test Queue Empty"
UnrealEditor-Cmd.exe <Portfolio.uproject> -run=CDodgeAssets -unattended -NullRHI -nosound
```
