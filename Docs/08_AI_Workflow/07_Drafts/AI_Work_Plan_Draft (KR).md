# AI Work Plan Draft

## 1. 목적

본 문서는 Codex를 적극적으로 활용하기 전에 고려한 작업 방식과 운영 후보를 정리한 초기 구상 문서다.

현재 작업 흐름과 운영 기준은 `../03_Operation/AI_Workflow_Operation_Guide (KR).md`와 `../04_Work_Pipeline/AI_Work_Pipeline (KR).md`에서 관리한다. 본 문서는 초기 구상과 원문 근거를 보관하는 Draft다.

AI 기반 작업 흐름은 현재 다음 순서로 고려하고 있다.

---

## 2. 작업 흐름 초안

```yaml
1. 목표 확인
2. 현재 구조 탐색
3. 아이디어 계획
4. 구조 제안
5. 적용 및 수정
6. 검증 및 안정화
7. 병합
8. 문서화 및 관리
```

각 단계는 사용자의 자연어 요청을 기술적 작업 단위로 해석하고, 필요한 입력과 산출물을 분리하기 위한 후보 흐름이다.

---

## 3. 작업 시 고려할 기준

```yaml
고려 기준
-> 작업 목표
-> 변경 위험
-> 검증 필요성
-> 문서화 필요성
-> 사용자 확인이 필요한 결정
```

구조를 제안할 때는 다음 기준 항목을 함께 검토한다.

```yaml
구조 제안 기준
-> 책임 경계
-> 변경 범위
-> 비범위
-> 단계별 적용 가능성
-> 실패 또는 미검증 항목
```

---

## 4. 리팩터링 논의 방식

리팩터링은 바로 구현 요청으로 처리하기보다, 먼저 문제 인식과 구조 탐색을 거친다.

```yaml
리팩터링 논의 흐름
-> 현재 문제가 무엇인지 확인
-> 관련 코드와 문서를 탐색
-> 책임 경계와 변경 위험을 분석
-> 작은 변경 단위로 나눔
-> 사용자에게 선택지와 추천 순서를 제시
```

---

## 5. Codex 활용 구상

```yaml
Default Mode
-> 계획이 정리된 뒤 실제 수정 / 검증 / 문서화를 진행

IDE Context
-> 현재 코드 / 문서 / 파일 상태를 공유해 탐색 효율을 높임

Plan Mode
-> 구현 전 목표, 범위, 책임, 검증 기준을 정리

Goal
-> 여러 턴에 걸친 장기 리팩터링이나 대규모 정리 작업 추적
```

---

## 6. 기록 / 문서화 메모

```yaml
문서화 후보
-> Work Checklist
-> Bug Report
-> System Architecture
-> Technical Document
-> PR Document
-> Prompt
-> Milestone / Roadmap
```

문서화 후보는 작업 결과를 남길 수 있는 산출물 목록이다.

```yaml
문서 양식 후보
-> Work Checklist
-> Bug Report
-> System Architecture
-> Verification Log
-> PR Document
-> Technical Document
```

문서 양식 후보는 별도 작성 양식과 작성 타이밍을 정리해야 하는 산출물 목록이다.

---

## 7. 다음 선택지 메모

```yaml
선택지 유형
-> 이어서 진행
-> 분기 작업
-> 점검 / 검토
-> 마감 작업
-> 작업 전환 제안
```

필요하면 `필수 / 우선 / 권장 / 선택 / 보류` 정도의 우선순위 표시를 붙인다.

---

## 8. 남은 고민

```yaml
남은 고민
-> 사용자 아이디어 전달 양식
-> 계속 수정할 항목 선정 기준
-> 검증 기준과 변경 위험의 연결 방식
-> 미검증 항목 기록 방식
```
