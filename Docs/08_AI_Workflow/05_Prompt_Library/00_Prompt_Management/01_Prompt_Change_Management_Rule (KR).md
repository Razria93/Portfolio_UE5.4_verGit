# Prompt Change Management Rule

## 1. 목적

본 문서는 Prompt Library를 운영하면서 발견한 최신 문서 패턴을 수집하고, Prompt 반영 후보로 관리하며, 승인 후 반영하고, 반영 이후 유지관리하는 기준을 정리한다.

Prompt 변경은 산출물 생성 기준을 바꾸는 작업이므로 일반 문서 수정과 분리해 관리한다.

---

## 2. 적용 범위

```yaml
적용 대상
-> 최근 문서 패턴 수집
-> Prompt 반영 후보 관리
-> Prompt 변경 승인
-> Prompt 변경 검증
-> Prompt 반영 후 유지관리
```

개별 Prompt의 작성 방식은 해당 Prompt 파일에서 관리하고, Prompt Library의 구조 / 이름 / 상태 / Archive 기준은 `04_Prompt_Library_Maintenance_Blueprint (KR).md`를 따른다.

---

## 3. 최근 문서 패턴 수집 기준

최근 문서 패턴 수집은 Prompt를 즉시 수정하기 위한 작업이 아니라, 실제 산출물에서 반복되거나 의미가 큰 작성 기준을 후보로 관리하기 위한 작업이다.

```yaml
수집 대상
-> 반복 적용된 섹션 구조, 용어 표기, 문체, 관련 문서 연결 방식
-> 코드 책임, 검증 결과, 완료 판단, Branch 시점처럼 의미 왜곡 위험이 있는 판단 기준
-> Prompt 기준과 실제 작성 패턴이 달라진 지점
```

```yaml
수집 제외
-> 단일 문서의 표현 취향
-> 해당 Branch 문맥에만 맞는 일회성 설명
-> 사용자가 명시적으로 폐기한 표현
```

```yaml
수집 방식
-> 작업 중 발견한 패턴은 자동으로 후보 기록할 수 있음
-> Prompt 파일 수정은 사용자 승인 전까지 수행하지 않음
-> 결과 보고 시 이번 작업에서 발견된 Prompt 반영 후보로 노출
```

---

## 4. Prompt 반영 후보 관리 기준

수집된 문서 패턴은 적용 범위와 위험도를 기준으로 분류한 뒤 반영 여부를 판단한다.

```yaml
후보 분류
문서 한정
-> 특정 PR / Bug Report / Work List에만 적용

문서 유형 한정
-> PR, Bug Report, Work List처럼 특정 문서군에 적용

공통 양식
-> 여러 문서 유형에 공통 적용

고위험 기준
-> 완료 / 검증 / 코드 책임 / Branch 기준처럼 오해 위험이 큰 기준
```

```yaml
후보화 기준
-> 일반 기준은 서로 다른 산출물 2개 이상에서 반복되면 후보화
-> 고위험 기준은 1회만 발생해도 후보로 노출
-> 기존 Prompt와 실제 산출물 패턴이 달라 결과 예측성이 떨어지면 후보화
```

```yaml
후보 관리
-> 후보는 즉시 반영하지 않고 반영 / 보류 / 문서 한정 / 폐기 중 하나로 판단
-> 보류 후보는 `02_Prompt_Pattern_Candidates (KR).md`에 남기고 같은 기준이 반복되면 재검토
-> 폐기 후보는 사용자가 반대한 이유나 폐기 근거를 남김
```

---

## 5. Prompt 변경 승인 기준

Prompt 변경은 사용자 명시 요청 또는 승인 이후 수행한다.

```yaml
승인 전 보고 항목
-> 변경 대상 Prompt
-> 변경하려는 기준
-> 후보가 나온 산출물 근거
-> 예상 영향 범위
-> 위험도
-> 충돌 가능성이 있는 Prompt
```

```yaml
변경 위험도
낮음
-> 기존 기준을 더 명확히 설명함
-> 오탈자, 섹션 위치, 표현 중복을 정리함
-> 결과물의 구조나 판단 기준을 바꾸지 않음

중간
-> 특정 산출물 유형의 섹션 선택, 용어 표기, 관련 문서 연결 기준을 바꿈
-> 기존 결과물 일부의 표현이나 구성이 달라질 수 있음

높음
-> 여러 Prompt에 걸친 공통 규칙을 바꿈
-> 작업 프로세스, 완료 기준, 검증 기준, 위험 판단 기준을 바꿈
-> Prompt 삭제 / 병합 / 대체 / Archive 전환을 수행함
```

위험도가 중간 이상이면 변경 전 영향 범위와 예상되는 결과 변화, 충돌 가능성을 먼저 정리한다.

---

## 6. Prompt 변경 검증 기준

Prompt를 추가 / 삭제 / 보완 / 변경한 뒤에는 다음을 확인한다.

```yaml
검증 기준
-> 같은 역할의 Prompt와 기준이 충돌하지 않는가
-> 상위 Blueprint / Custom Blueprint / 개별 Prompt의 책임 경계가 유지되는가
-> 변경된 기준이 최근 실제 산출물 패턴과 일치하는가
-> 변경으로 인해 이전 산출물 해석이 과하게 바뀌지 않는가
-> 삭제 / 병합 / 대체 시 참조 경로와 역할 설명이 함께 갱신되었는가
-> 변경 결과가 사용자에게 명시적으로 보고되었는가
```

필요하면 보조 검토를 통해 충돌 여부, 영향 범위, 예시 결과 변화를 분리해서 확인한다.

---

## 7. Prompt 반영 후 유지관리 기준

Prompt에 반영된 기준은 실제 산출물에서 다시 검증하고, 시간이 지나 충돌하거나 구버전화되지 않는지 관리한다.

```yaml
반영 후 확인
-> 최신 산출물 패턴과 Prompt 기준이 다시 일치하는가
-> 같은 역할의 Prompt와 충돌하지 않는가
-> 다른 문서 유형에 과하게 확장되지 않았는가
-> 예전 산출물을 잘못 해석하게 만들지 않는가
```

```yaml
유지관리 상태
-> 반영 완료 기준은 이후 실제 산출물에서 다시 검증
-> 사용 빈도가 낮거나 충돌이 생긴 기준은 보완 후보 / 축약 후보 / 대체 후보 / Archive 후보로 재분류
-> 삭제 / 병합은 즉시 수행하지 않고 참조 갱신과 대체 기준 확인 후 진행
```

```yaml
보고 기준
-> Prompt 변경 후 결과 보고에는 변경된 기준, 영향 범위, 검증 결과를 포함
-> 작업 중 Prompt와 다른 최신 문서 패턴을 적용했다면 다음 보고에서 명시
```
