# Prompt Format Blueprint

## 1. 목적

본 문서는 반복 사용할 Prompt를 작성할 때 필요한 기본 구성과 섹션 순서를 정리한다.

각 섹션 내부에 들어갈 요청 설계 품질은 `02_Prompt_Engineering_Blueprint (KR).md` 기준으로 채운다.

특정 프로젝트, 도구, 문서 체계, 파일 경로, 산출물 이름은 이 문서에 직접 포함하지 않는다. 필요한 경우 별도 Prompt Custom Blueprint에서 추가 규칙으로 관리한다.

---

## 2. 적용 범위

이 가이드는 반복 사용할 Prompt를 작성, 수정, 검토할 때 적용한다.

```yaml
적용 대상
1. 작업 지시 Prompt
2. 분석 Prompt
3. 문서 작성 / 보완 Prompt
4. 검증 Prompt
5. 운영 점검 Prompt
```

일회성 요청 작성법, 모델별 요청 조정, 예시 기반 응답 유도는 `02_Prompt_Engineering_Blueprint (KR).md`에서 다룬다.

---

## 3. Prompt 기본 구조

이 섹션은 Prompt에 어떤 항목이 어떤 순서로 들어가는지 정하는 상위 양식이다.

```yaml
기본 구조
기본 섹션 [항상 포함]
1. 목적
2. 사용 시점
3. 사용 방법
4. 복사용 Prompt

작업 계약 섹션 [조건부 포함]
5. 입력 기준
6. 출력 기준
7. 범위 / 비범위
8. 제약 조건

품질 / 처리 섹션 [조건부 포함]
9. 모호성 처리 기준
10. 검증 기준
11. 완료 / 실패 / 미검증 처리 기준

Library 관리 섹션 [Library 등록 시 포함]
12. 기존 Prompt와 역할 경계

Lifecycle 섹션 [선택]
13. 계속 수정할 항목
```

```yaml
상태 기준
항상 포함
-> 반복 사용할 Prompt라면 기본적으로 포함

조건부 포함
-> 작업 성격상 범위, 입력, 출력, 제약, 검증, 모호성 처리가 필요한 경우 포함

Library 등록 시 포함
-> Prompt Library에 새 Prompt를 추가하거나 기존 Prompt와 충돌 가능성이 있을 때 포함

선택
-> 초안, 실사용 보완, 유지보수 메모가 필요한 경우 포함
```

```yaml
항목 설명
목적
-> Prompt가 해결하려는 작업 유형과 기대 결과를 설명

사용 시점
-> 이 Prompt를 언제 선택해야 하는지 설명

사용 방법
-> 선택한 Prompt를 실제 작업에 어떻게 적용해야 하는지 설명

복사용 Prompt
-> 실제 작업 세션에 붙여넣을 수 있는 요청 본문
-> 해설, 작성 의도, 관리 메모와 분리

입력 기준
-> 사용자가 제공해야 할 정보와 참고 자료

출력 기준
-> AI가 반환해야 할 결과의 형태와 포함 항목

범위 / 비범위
-> 다루는 범위와 제외할 범위

제약 조건
-> 따라야 할 제한, 금지 조건, 확인 필요 조건

모호성 처리 기준
-> 질문 / 선택지 / 가정 / 미확인 표시 기준

검증 기준
-> 결과가 목적을 충족했는지 확인하는 기준

완료 / 실패 / 미검증 처리 기준
-> 결과 상태를 어떻게 구분할지 설명

기존 Prompt와 역할 경계
-> 기존 Prompt와의 중복, 대체 가능성, 역할 차이

계속 수정할 항목
-> 실사용 후 보완할 내용
```

복사용 Prompt와 해설 / 운영 기준은 분리한다. 복사용 Prompt는 실제 작업 세션에 붙여넣을 수 있어야 하고, 해설 / 운영 기준은 수정 근거를 이해할 수 있도록 작성한다.

## 4. 조건부 섹션 포함 기준

이 섹션은 Prompt에 조건부 섹션을 포함할지 판단할 때 사용하는 기준이다. 이 문서는 내용을 어떻게 작성할지보다 어떤 섹션을 둘지 판단한다. 섹션 내부 내용 설계는 `02_Prompt_Engineering_Blueprint (KR).md`를 따른다.

```yaml
입력 기준
-> 사용자가 제공해야 할 정보가 반복적으로 필요한 Prompt에 포함

출력 기준
-> 결과 형식이나 포함 항목을 고정해야 하는 Prompt에 포함

제약 조건
-> 금지 조건, 제외 범위, 사용자 확인 조건이 있는 Prompt에 포함

범위 / 비범위
-> 작업 범위가 넓거나 제외 범위가 없으면 오해가 생길 수 있을 때 포함

모호성 처리 기준
-> 입력 부족 / 변동 가능성이 있고 AI가 임의로 가정하면 결과 품질이 흔들릴 때 포함

검증 기준
-> 결과의 성공 여부를 확인해야 하는 Prompt에 포함
-> 누락, 충돌, 미검증 항목을 구분해야 하는 Prompt에 포함

완료 / 실패 / 미검증 처리 기준
-> 검증 필요성이 있거나 미확인 항목이 완료처럼 보일 위험이 있을 때 포함

기존 Prompt와 역할 경계
-> Prompt Library에 새 Prompt를 추가할 때 중복 / 대체 / 병합 여부 판단을 위해 포함

계속 수정할 항목
-> 초안이거나 실사용하면서 개선할 여지가 있을 때 포함
```

---

## 5. Library 등록 전 확인

새 Prompt를 작성하기 전에는 같은 역할의 Prompt가 이미 있는지 확인한다.

중복 / 보완 / 병합 / 대체 / 삭제 판단 기준은 `04_Prompt_Library_Maintenance_Blueprint (KR).md`를 따른다.

---

## 6. 일반 원칙과 Custom 규칙 분리

```yaml
일반 원칙
-> 프로젝트와 무관하게 적용 가능한 Prompt 작성 기준

Custom 규칙
-> 특정 프로젝트, 도구, 사용자 선호, 산출물 체계에 맞춘 추가 기준
```

Custom 규칙은 일반 원칙에 특정 프로젝트, 도구, 사용자 선호를 적용하기 위한 추가 기준으로 관리한다. 일반 원칙과 충돌하는 경우에는 우선순위와 변경 이유를 명시한다.

---

## 7. Prompt 품질 점검 체크리스트

```yaml
품질 점검
-> 항상 포함 섹션이 모두 있는가
-> 조건부 섹션을 포함하거나 제외한 이유가 분명한가
-> 목적이 명확히 드러나는가
-> 사용 시점이 명확히 드러나는가
-> 사용 방법이 명확히 드러나는가
-> 입력값과 출력값이 분리되어 있는가
-> 범위와 비범위가 분리되어 있는가
-> 제약 조건이 있는가
-> 모호성 처리 기준이 필요한 경우 포함되어 있는가
-> 검증 기준이 있는가
-> 완료 / 실패 / 미검증 처리 기준이 필요한 경우 포함되어 있는가
-> 섹션 내부 내용 설계를 Prompt Engineering Blueprint 기준으로 채울 수 있는가
-> 복사용 Prompt와 해설이 분리되어 있는가
-> 미검증 항목을 구분할 섹션이 필요한지 판단했는가
-> 기존 Prompt와 역할 경계 섹션이 필요한 경우 포함되어 있는가
-> 초안 Prompt인 경우 계속 수정할 항목이 남아 있는가
```
