# Prompt Library Maintenance Blueprint

## 1. 목적

본 문서는 Prompt Library라는 Prompt 집합을 유지보수할 때 적용하는 문맥 독립적인 관리 기준을 정리한다.

Prompt Format Blueprint가 개별 Prompt의 양식과 섹션 구조를 다룬다면, 본 문서는 작성된 Prompt들의 위치, 이름, 상태, 중복, 참조, 수명주기, 후속 관리 기준을 다룬다.

특정 프로젝트의 폴더 구조, 문서 이름, 작업 흐름, Backlog 위치는 이 문서에 직접 포함하지 않는다. 필요한 경우 별도 Prompt Custom Blueprint에서 추가 규칙으로 관리한다.

---

## 2. 관리 대상

```yaml
관리 대상
-> Prompt Library 구조
-> Prompt 파일명 규칙
-> Prompt 관리 상태
-> 중복 / 구버전 / 역할 충돌 판단
-> Archive / 삭제 / 대체 기준
-> 링크 / 참조 갱신
-> 후속 관리 목록 반영 기준
```

---

## 3. Prompt Library 구조 원칙

Prompt Library는 사용 목적과 사용 시점을 기준으로 분류한다.

```yaml
분류 기준
-> 작업 규칙
-> 분석 / 판단 근거
-> 문서 작성
-> 기능 전용 작업
-> 리뷰 / 검증
-> 운영 점검
```

폴더명은 항목의 역할을 드러내야 하며, 특정 작업이 끝난 뒤에도 유지할 가치가 있는 구조로 둔다.

---

## 4. 파일명 규칙

Prompt 파일명은 검색 가능성과 역할 식별성을 우선한다.

```yaml
권장 형식
-> [대상]_[용도]_Prompt

대상
-> Prompt가 다루는 도메인, 산출물, 기능, 작업 범위

용도
-> 작업 규칙
-> 분석
-> 작성
-> 검증
-> 운영 점검
```

구체적인 접두어, 번호 체계, 언어 표기, 폴더별 이름 규칙은 각 Prompt Library의 Prompt Custom Blueprint에서 정한다.

---

## 5. 상태 기준

```yaml
유지
-> 역할이 명확하고 현재 기준과 충돌하지 않음

보완 후보
-> 유지하되 실사용 후 내용 보강이 필요함

축약 후보
-> 유용하지만 다른 Prompt와 분석 / 규칙이 많이 겹침

병합 후보
-> 두 Prompt가 같은 사용 시점과 목적을 가짐

대체 후보
-> 새 Prompt가 기존 Prompt의 역할을 더 정확히 수행함

Archive 후보
-> 현재 작업에는 필요하지 않지만 기록 가치가 있음

삭제 후보
-> 중복이 크고 별도 역할도 없으며 유지할 이유가 약함
```

삭제 후보는 즉시 삭제하지 않고, 역할 재정의 / 축약 / 병합 / 대체 가능성을 먼저 검토한다.

---

## 6. 상태 전환 기준

```yaml
보완 후보 -> 유지
-> 보완 내용이 반영되고 사용 시점 / 역할 / 검증 기준이 명확해짐

축약 후보 -> 유지
-> 중복 설명이 제거되고 실사용 Prompt 역할이 선명해짐

병합 후보 -> 유지 / Archive / 삭제 후보
-> 병합 후 남는 Prompt는 유지하고, 흡수된 Prompt는 기록 가치에 따라 Archive 또는 삭제 후보로 전환

대체 후보 -> Archive / 삭제 후보
-> 대체 Prompt가 링크, 역할, 사용 기준을 모두 흡수함

Archive 후보 -> Archive
-> 과거 문맥 보존 가치가 현재 사용 가치보다 클 때 Archive로 전환

삭제 후보 -> 삭제
-> 별도 역할과 기록 가치가 없고, 대체 Prompt와 참조 갱신이 확인된 경우 삭제
```

상태 전환 시에는 변경 이유, 영향받는 Prompt, 참조 갱신 필요 여부를 함께 기록한다.

---

## 7. 중복 / 구버전 판단 기준

```yaml
중복 판단
-> 사용 시점이 같은가
-> 입력과 출력이 같은가
-> 같은 산출물을 같은 방식으로 작성하는가
-> 한 Prompt가 다른 Prompt의 내용을 대부분 포함하는가

구버전 판단
-> 현재 기준과 충돌하는가
-> 파일명 / 폴더명 / 용어가 현재 기준과 다른가
-> 유지 시 사용자가 오래된 기준을 최신 기준으로 오해할 가능성이 있는가
```

---

## 8. Archive / 삭제 / 대체 기준

```yaml
Archive 권장
-> 완료된 기능 또는 과거 작업 문맥을 보존할 필요가 있음

삭제 권장
-> 새 Prompt가 역할을 완전히 대체함
-> 별도 기록 가치가 없음
-> 유지 시 구버전 기준을 최신 기준처럼 보이게 할 위험이 큼

대체 권장
-> 기존 문서의 목적은 유지하지만 이름, 구조, 기준이 현재 운영 체계와 맞지 않음
```

삭제 / 대체 판단은 변경 이유, 영향받는 링크, 대체 Prompt를 확인한 뒤 수행한다.

---

## 9. 링크 / 참조 갱신 기준

Prompt 파일명, 폴더명, 역할이 바뀌면 다음을 함께 확인한다.

```yaml
확인 대상
-> Index
-> 후속 관리 목록
-> 관련 Prompt
-> 관련 산출물 작성 기준
-> Prompt를 참조하는 운영 문서
```

참조 갱신은 파일 이동 또는 rename과 같은 변경 작업의 일부로 처리한다. 변경 후에는 구 파일명, 구 경로, 구 역할명이 남아 있는지 검색한다.

---

## 10. 후속 관리 목록 반영 기준

즉시 처리하지 않을 항목은 별도 후속 관리 목록에 기록한다.

```yaml
기록 대상
-> 후속 작성 후보
-> 추가 검토 후보
-> 삭제 / Archive 판단 보류 항목
-> 명칭 전환 대기 항목
-> 실사용 후 보완 항목
```

후속 관리 목록의 구체적인 이름, 위치, 상태 체계는 각 Prompt Library의 Prompt Custom Blueprint에서 정한다.

---

## 11. 유지보수 트리거

Prompt Library는 다음 상황에서 점검한다.

```yaml
점검 트리거
-> 새 Prompt 추가
-> Prompt 파일명 / 폴더명 변경
-> Prompt 관리 상태 변경
-> Prompt Library 구조 변경
-> 기존 Prompt와 역할 충돌 발생
-> 기준 문서 또는 Custom 규칙 변경
```
