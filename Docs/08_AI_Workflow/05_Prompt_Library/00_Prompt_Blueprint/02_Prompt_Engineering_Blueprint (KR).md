# Prompt Engineering Blueprint

## 1. 목적

본 문서는 Prompt의 요청 내용을 설계하고 개선할 때 사용하는 보편 기준을 정리한다.

Prompt Engineering은 요청의 목적, 지시문, Context, 출력 형식, 제약 조건, 예시, 평가 기준을 조정해 모델의 응답 방향을 좁히는 작업이다.

이 가이드는 `01_Prompt_Format_Blueprint (KR).md`가 정의한 양식 안에 들어갈 내용 품질을 다룬다.

참고 기준은 다음 문서를 사용한다.

```yaml
참고 기준
-> OpenAI Prompt engineering guide: https://platform.openai.com/docs/guides/prompt-engineering
-> OpenAI Help Center prompt best practices: https://help.openai.com/en/articles/10032626-prompt-engineering-best-practices-for-chatgpt
```

이 가이드는 Prompt Format Blueprint의 기본 구조에 들어갈 요청 내용을 설계하거나, 기존 Prompt의 응답 품질을 개선할 때 적용한다.

```yaml
Prompt Format Blueprint 기본 구조와 연결되는 적용 대상
-> 복사용 Prompt 작성
-> 입력 기준 / 출력 기준 / 제약 조건 설계
-> 검증 기준 / 완료 / 실패 / 미검증 처리 기준 설계
-> 모호성 처리 기준 설계
-> 계속 수정할 항목에 반영할 평가 / 반복 개선 기준 설계

-> 일회성 작업 요청 작성

```

Prompt Format Blueprint는 섹션 구조를 정하고, 이 가이드는 각 섹션 안에 들어갈 요청 내용을 설계한다.

## 3. Prompt Engineering 기본 원칙

```yaml
기본 원칙
-> 요청 목적을 명확히 제시
-> 필요한 Context를 충분히 제공
-> 불필요한 Context는 제외
-> 원하는 출력 형식을 명시
-> 제약 조건과 금지 조건을 분리
-> 모호한 입력은 질문 / 선택지 / 가정으로 처리
-> 결과를 확인할 평가 기준을 포함
-> 결과를 보고 Prompt를 반복 개선
```

좋은 Prompt는 모델이 무엇을 해야 하는지뿐 아니라, 어떤 정보를 근거로 어떤 형식의 결과를 내야 하는지까지 제한한다.

## 4. 목적 / 사용 시점 / 사용 방법 설계 기준

반복 사용할 Prompt는 목적, 사용 시점, 사용 방법이 분리되어 있어야 한다.

```yaml
목적
-> Prompt가 해결할 작업 유형과 기대 결과를 한 문장 또는 짧은 문단으로 정의

사용 시점
-> 이 Prompt를 선택해야 하는 상황과 선택하지 말아야 할 상황을 구분

사용 방법
-> Prompt를 적용하는 순서, 필요한 입력, 결과 확인 방식을 설명
```

---

## 5. 지시문 / Context / 출력 형식 설계

요청은 `지시문`, `Context`, `출력 형식`을 분리해 작성한다.

반복 사용할 Prompt에서는 이 기준을 `복사용 Prompt`, `입력 기준`, `출력 기준`, `제약 조건` 섹션을 채울 때 사용한다.

```yaml
지시문
-> 수행할 작업
-> 답변 관점
-> 우선순위
-> 제한 사항

Context
-> 참고해야 할 배경
-> 입력 자료
-> 현재 상태
-> 판단에 필요한 조건

출력 형식
-> 문단 / 표 / 목록 / 코드블록
-> 필수 포함 항목
-> 제외할 항목
-> 응답 길이 또는 밀도
```

```yaml
반복 사용할 Prompt의 입력 / 출력 / 제약 조건 설계 예시
입력 기준
-> 작업 목표
-> 관련 자료
-> 변경 범위
-> 사용해야 할 기준
-> 검증해야 할 항목
-> 사용자 확인이 필요한 항목

출력 기준
-> 분석 결과
-> 작성 결과
-> 변경 제안
-> 검증 결과
-> 미검증 항목
-> 후속 작업 범위

제약 조건
-> 수정하지 않을 범위
-> 사용자 확인이 필요한 결정
-> 추정으로 쓰면 안 되는 내용
-> 사용할 수 없는 도구 / 환경
-> 따라야 할 외부 기준

범위
-> Prompt가 다룰 작업
-> Prompt가 만들거나 검토할 산출물
-> Prompt가 참고해야 할 대상

비범위
-> 이번 Prompt가 다루지 않을 작업
-> 제외할 판단
-> 후속 작업으로 넘길 항목
```

Context는 요청 수행에 필요한 정보가 정확히 포함되도록 구성한다.

## 6. 모호성 / 부족한 입력 처리 기준

Prompt에는 입력이 부족할 때의 처리 방식을 명시할 수 있다.

반복 사용할 Prompt에서는 이 기준을 `모호성 처리 기준` 또는 `복사용 Prompt`의 입력 부족 처리 문장에 반영한다.

```yaml
처리 방식
-> 질문: 결정 없이는 진행하면 위험한 경우
-> 선택지: 가능한 방향이 여러 개이고 tradeoff가 다른 경우
-> 가정 명시: 영향이 작고 합리적인 기본값이 있는 경우
-> 탐색 우선: 모델 또는 작업자가 확인 가능한 정보가 있는 경우
-> 미확인 표시: 검증할 수 없는 내용을 결과에 포함해야 하는 경우
```

중요한 결정이 필요한데 입력이 부족한 경우에는 결과를 단정하지 않고 질문이나 선택지로 분리한다.

## 7. 예시 제공 기준

예시는 모델이 원하는 패턴을 이해해야 할 때 사용한다.

```yaml
예시가 유용한 경우
-> 출력 형식이 엄격함
-> 판단 기준이 추상적임
-> 좋은 결과와 나쁜 결과의 차이를 보여줘야 함
-> 특정 문체나 구조를 반복해야 함

예시 작성 기준
-> 입력과 출력 쌍을 함께 제공
-> 다양한 케이스를 포함
-> 반례나 실패 사례를 필요한 만큼 포함
-> 예시가 실제 요청보다 우선하지 않도록 범위를 명시
```

예시는 판단 패턴과 출력 형식을 학습시키기 위한 기준이다.

## 8. 완료 / 실패 / 미검증 처리 기준

반복 사용할 Prompt는 필요한 경우 결과 상태를 완료, 실패, 미검증으로 구분할 수 있어야 한다.

```yaml
완료
-> 요청 목적과 필수 출력 기준을 충족한 상태

실패
-> 요청 목적을 충족하지 못했거나 필수 조건을 위반한 상태

미검증
-> 결과를 단정할 근거가 부족하거나 외부 확인이 필요한 상태
```

---

## 9. 평가 / 반복 개선 기준

Prompt는 결과를 기준으로 반복 개선한다.

반복 사용할 Prompt에서는 이 기준을 `검증 기준`과 `계속 수정할 항목`에 반영한다.

```yaml
평가 기준
-> 요청 목적을 충족했는가
-> 필수 입력이 반영되었는가
-> 출력 형식을 지켰는가
-> 제약 조건을 위반하지 않았는가
-> 모호한 항목을 단정하지 않았는가
-> 검증 가능한 결과를 제공했는가
-> 필수 항목 누락 여부를 확인했는가
-> 요청 안의 기준들이 서로 충돌하지 않는가
-> 실행 가능한 검증과 실행 불가능한 검증을 분리했는가
-> 확인하지 못한 항목을 미검증으로 기록했는가
```

개선이 필요한 경우에는 Prompt의 `지시문`, `Context`, `출력 형식`, `제약 조건`, `예시`, `평가 기준` 중 어느 부분이 부족했는지 확인한다.

---

## 10. 모델 / 작업 유형에 따른 조정 기준

Prompt는 모델 특성과 작업 유형에 따라 조정한다.

```yaml
조정 기준
-> 복잡한 추론 작업은 목표 / 조건 / 단계 / 검증 기준을 더 명확히 작성
-> 단순 생성 작업은 출력 형식과 제약 조건을 간결하게 작성
-> 코드 / 문서 작업은 변경 범위와 검증 기준을 포함
-> 빠른 초안 작업은 완성도보다 방향성과 누락 항목을 우선
-> 최종 검수 작업은 오류, 누락, 불일치, 검증 가능성을 우선
```

모델 또는 실행 환경이 바뀌면 같은 Prompt라도 결과가 달라질 수 있으므로, 중요한 Prompt는 결과를 비교하고 개선한다.

## 11. Prompt Blueprint 간 역할 경계

```yaml
Prompt Format Blueprint
-> Prompt의 양식, 섹션 구조, 입력 / 출력 / 검증 항목 구성 기준

Prompt Engineering Blueprint
-> AI 응답을 유도하는 요청 설계 기준

Prompt Library Maintenance Blueprint
-> 작성된 Prompt의 상태 / 중복 / 참조 / Archive 관리 기준

Prompt Custom Blueprint
-> 특정 프로젝트, 도구, 사용자 선호, 산출물 체계에 맞춘 추가 적용 기준
```

Prompt Format Blueprint가 Prompt의 양식과 섹션 구조를 정하고, Prompt Engineering Blueprint는 그 양식 안에 들어갈 요청 내용을 설계한다. Prompt Custom Blueprint는 두 기준을 특정 작업 환경에 맞게 확장한다.

```yaml
품질 점검

-> 입력 부족 시 처리 기준이 있는가
-> 결과 평가 기준이 있는가
-> 완료 / 실패 / 미검증 상태를 구분할 수 있는가
-> 설계한 요청 기준이 반복 사용할 Prompt의 복사용 Prompt / 입력 / 출력 / 제약 / 검증 섹션에 반영 가능한가
-> 반복 개선할 수 있는 기준이 남아 있는가
```
