# Bug Report Writing Prompt

## 1. 목적

재현 조건, 기대 결과, 실제 결과, 원인, 수정, 검증 결과를 Bug Report로 정리한다.

---

## 2. 사용 시점

```yaml
사용 시점
-> 재현 가능한 문제가 발생했을 때
-> 버그 수정 결과를 문서로 남겨야 할 때
-> 원인과 수정, 검증 결과를 연결해야 할 때
```

---

## 3. 사용 방법

대상 문제, 재현 조건, 관련 코드 / 문서, 수정 결과를 제공하고 `복사용 Prompt`를 사용한다.

---

## 4. 복사용 Prompt

````text
아래 문제를 Bug Report 형식으로 작성 또는 보완해줘.

대상 문제:
- [증상 / 문서 경로 / issue]

관련 문서:
- Work List:
- Bug Report:
- System Architecture:
- System Design Records:
- Engine Technique Document:
- Engine Implementation Records:
- Verification Log:
- PR Document:
- Portfolio Technical Document:

작성 목표:
- 재현 조건 / 기대 결과 / 실제 결과 / 원인 / 수정 / 검증 결과를 분리해줘.
- 코드의 실제 타입명 / API / struct / enum / 파일명을 기준으로 작성해줘.
- 버그가 발생한 처리 흐름과 책임 경계를 추적 가능하게 설명해줘.
- 수정이 원인을 어떻게 제거했는지 연결해줘.
- 검증 결과는 실제 확인한 결과만 작성해줘.

권장 구조:
1. 제목
2. 날짜
3. 상태
4. Branch
5. 요약
6. 환경
7. 재현 방법
8. 기대 결과 / 실제 결과
9. 원인
10. 수정
11. 검증 결과
12. 비고
````

---

## 5. 입력 기준

```yaml
입력 기준
-> 증상
-> 재현 조건
-> 기대 결과
-> 실제 결과
-> 관련 코드 / 문서
-> 수정 내용
-> 검증 결과
```

---

## 6. 출력 기준

```yaml
출력 기준
-> 재현 조건
-> 기대 결과 / 실제 결과
-> 원인
-> 수정
-> 검증 결과
-> 미검증 항목
```

---

## 7. 범위 / 비범위

```yaml
범위
-> Bug Report 작성 / 보완

비범위
-> 버그 수정 구현
-> PR Document 작성
-> Portfolio Technical Document 압축
```

---

## 8. 제약 조건

```yaml
제약 조건
-> 추정 원인은 추정으로 표시
-> 원인과 수정이 연결되지 않는 설명은 비고로 분리
-> 최신 구조를 과거 버그 원인으로 덮어쓰지 않음
```

---

## 9. 모호성 처리 기준

```yaml
모호한 경우
-> 재현 근거와 추정 근거를 분리
-> 현재 코드 기준 참고 사항은 본문과 분리
```

---

## 10. 검증 기준

```yaml
검증 기준
-> 재현 조건이 명확한가
-> 원인과 수정이 연결되는가
-> 실제 수행한 검증과 미검증 항목이 분리되는가
```

---

## 11. 완료 / 실패 / 미검증 처리 기준

```yaml
완료
-> 버그 흐름과 검증 결과가 분리됨

실패
-> 재현 조건 또는 수정 근거 확인 불가

미검증
-> PIE / Editor / Asset 검증 필요
```

---

## 12. 기존 Prompt와 역할 경계

```yaml
Bug Report Writing Prompt
-> 개별 버그 분석 문서 작성

Troubleshooting Summary Prompt
-> 여러 Bug Report를 유형별 기술 문서로 압축
```

---

## 13. 계속 수정할 항목

```yaml
후속 보완 후보
-> 버그 유형별 출력 템플릿
```
