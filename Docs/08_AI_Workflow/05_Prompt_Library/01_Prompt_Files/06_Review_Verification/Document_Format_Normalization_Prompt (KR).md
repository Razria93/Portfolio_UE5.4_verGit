# Document Format Normalization Prompt

## 1. 목적

문서군 전체의 파일명, 상단 메타 섹션, 본문 제목, 상태값, 브랜치 표기, 문체, 공백을 공통 양식 기준으로 점검하고 정리한다.

이 Prompt는 문서 내용을 새로 해석하거나 확장하지 않는다. 기존 문서의 의미는 유지하고, 양식과 표현만 일관되게 맞춘다.

---

## 2. 사용 시점

```yaml
사용 시점
-> 문서군 전체에 공통 양식을 적용할 때
-> 파일명 / 본문 제목 / 날짜 / 상태 / 브랜치 표기를 통일할 때
-> 문서 제목에서 gitmoji, milestone 번호, issue 번호 같은 관리 표기를 제거할 때
-> 명사형 어미를 기본체로 정리할 때
-> PR / Commit 전 문서 양식과 공백을 검증할 때
```

---

## 3. 사용 방법

대상 문서 또는 폴더 경로, 최근 변경 목적, 수정 허용 범위를 제공하고 `복사용 Prompt`를 사용한다.

검토만 필요한 경우에는 수정하지 않고 Findings와 수정 계획을 요청한다. 수정까지 필요한 경우에는 변경 범위를 명시하고, 적용 후 검증 결과를 요청한다.

---

## 4. 복사용 Prompt

````text
대상 Markdown 문서를 공통 양식 기준에 맞게 점검하고 정리해줘.

의미를 새로 만들거나 내용을 과하게 확장하지 말고, 파일명 / 상단 메타 / 문체 / 공백 정리만 수행해줘.

대상 경로:
- [문서 / 폴더 경로 입력]

최근 변경 목적:
- [최근 변경 목적 입력]

수정 허용 범위:
- [검토만 / 직접 수정까지 허용 / 특정 항목만 수정 등 입력]

## 1. 대상 기준

- 대상 문서 전체를 확인한다.
- 파일명 기준 문서 넘버링을 본문 제목 넘버링의 기준으로 사용한다.
  - 예: `B03_...md` -> `**B03: ...**`
  - 예: `P17_...md` -> `**P17: ...**`
- 파일명에 `(KR)`이 있으면 제거한다.
- 파일명 변경으로 내부 링크나 참조가 깨지면 함께 갱신한다.

## 2. 상단 메타 섹션

상단 메타 섹션은 다음 순서와 형태로 통일한다.

```md
# 문서 카테고리명

## 제목

**B03: 예시 제목**

## 날짜

**2026.06.10**

## 상태

- [x] **완료**

---

## 브랜치

- `feature/ai-bt-context`
```

### 제목

- 본문 제목은 반드시 Bold 처리한다.
- 본문 제목의 넘버링은 파일명 넘버링과 동일하게 맞춘다.
- 본문 제목에서 다음 요소를 제거한다.
  - gitmoji
  - milestone 번호
  - issue 번호 `(#xx)`
  - `(KR)`

### 날짜

- 날짜 섹션이 없으면 추가한다.
- 날짜가 확인되면 `**yyyy.mm.dd**` 형태로 통일한다.
- 날짜가 확인되지 않으면 `**추가요망**`으로 기재한다.

### 상태

- 상태 섹션명은 `상태`로 작성한다.
- 상태 값은 `- [ ] **진행중**` 또는 `- [x] **완료**`만 사용한다.
- 기존 상태 값은 문맥에 맞게 둘 중 하나로 치환한다.
  - `Done`, `Closed`, `Resolved` -> `완료`
  - `작성중`, `검토중`, `진행 중` -> `진행중`

### 브랜치

- 브랜치 섹션명은 `브랜치`로 작성한다.
- 상태와 브랜치 사이에는 반드시 구분선 `---`을 둔다.
- 브랜치는 단일 / 복수 모두 bullet list로 작성한다.
- 브랜치 값은 인라인 코드로 작성한다.
- 브랜치가 확인되지 않으면 `- **추가요망**`으로 기재한다.

## 3. 제거 대상

- `유형` 또는 `Type` 섹션이 있으면 제거한다.
- 유형 정보가 문서 의미상 필요하면 요약 문장에 자연스럽게 흡수한다.
- 기존 H1이 문서별 제목 역할을 하고 있으면 공통 문서 카테고리명으로 정리한다.

## 4. 문체 정리

명사형 어미를 기본체로 변경한다.

- 완료된 작업 설명은 `했다 / 됐다`로 정리한다.
  - `구성함` -> `구성했다`
  - `정리함` -> `정리했다`
  - `확인함` -> `확인했다`
  - `완료됨` -> `완료됐다`
- 현재 정책, 규칙, 조건 설명은 `한다 / 된다 / 필요하다`로 정리한다.
  - `필요함` -> `필요하다`
  - `아님` -> `아니다`

## 5. 검증

수정 후 다음을 확인한다.

- 파일명에 `(KR)`이 남아 있지 않다.
- 본문 제목에 gitmoji, milestone 번호, issue 번호, `(KR)`이 남아 있지 않다.
- 본문 제목 넘버링이 파일명 넘버링과 일치한다.
- 날짜가 `**yyyy.mm.dd**` 또는 `**추가요망**` 형태다.
- 상태가 `- [ ] **진행중**` 또는 `- [x] **완료**` 형태다.
- 상태와 브랜치 사이에 `---`이 있다.
- 브랜치가 단일 / 복수 모두 bullet list로 작성되어 있다.
- 브랜치 값이 인라인 코드 형식이다.
- 명사형 어미가 남아 있지 않다.
- `git diff --check`를 통과한다.

## 6. 결과 보고

다음 형식으로 결과를 요약한다.

1. 수정한 양식 범위
2. 수정한 문서 수
3. 남긴 `추가요망` 항목
4. 직접 수정하지 않은 후속 검토 후보
5. 검증 결과

제약 조건:
- 문서 의미를 새로 만들지 않는다.
- 완료 여부, 날짜, 브랜치를 임의 추정하지 않는다.
- 확인되지 않은 날짜와 브랜치는 `추가요망`으로 남긴다.
- 검토만 요청받은 경우 직접 수정하지 않는다.
````

```yaml
-> 최근 변경 목적
-> 수정 허용 범위
-> 필요한 경우 기준으로 삼을 문서 카테고리명
```

## 6. 출력 기준

```yaml
출력 기준
-> 수정한 양식 범위
-> 수정한 문서 수
-> 추가요망 항목
-> 후속 검토 후보
-> 검증 결과
```

---

## 7. 범위 / 비범위

```yaml
범위
-> 파일명 / 본문 제목 / 상단 메타 섹션 정리
-> 날짜 / 상태 / 브랜치 표기 통일
-> 유형 섹션 제거
-> 명사형 어미 정리
-> trailing whitespace 검증

비범위
-> 문서 내용 재해석
-> 문서 역할 변경
-> 완료 여부 임의 판정
-> 날짜 / 브랜치 임의 추정
-> 코드 리뷰
```

---

## 8. 제약 조건

```yaml
제약 조건
-> 의미보다 양식 정리를 우선하되, 의미를 훼손하지 않음
-> 파일명 넘버링을 본문 제목 넘버링의 최우선 기준으로 사용
-> 단일 브랜치도 bullet list로 표기하고, 브랜치 값은 인라인 코드로 작성
-> 확인되지 않은 값은 추가요망으로 남김
-> 문서 내용을 과하게 확장하지 않음
```

---

## 9. 모호성 처리 기준

```yaml
모호한 경우
-> 날짜가 여러 개면 상단 메타 날짜만 정리하고 나머지는 본문 맥락으로 유지
-> 상태 판단이 어렵다면 `- [ ] **진행중**`으로 두고 후속 검토 후보로 남김
-> 브랜치가 문서 안에서 확인되지 않으면 추가요망으로 남김
-> 유형 정보가 삭제하면 의미가 사라지는 경우 요약 문장에 최소로 흡수
-> H1이 카테고리명인지 문서 제목인지 불명확하면 즉시 변경하지 않고 후속 검토 후보로 남김
```

---

## 10. 검증 기준

```yaml
검증 기준
-> 파일명에 (KR)이 남아 있지 않은지 확인
-> 본문 제목에서 gitmoji / milestone 번호 / issue 번호 / (KR)이 제거되었는지 확인
-> 본문 제목 넘버링과 파일명 넘버링이 일치하는지 확인
-> 날짜가 **yyyy.mm.dd** 또는 **추가요망** 형태인지 확인
-> 상태가 `- [ ] **진행중**` 또는 `- [x] **완료**` 형태인지 확인
-> 상태와 브랜치 사이에 --- 구분선이 있는지 확인
-> 브랜치가 bullet list 형식이고 브랜치 값이 인라인 코드인지 확인
-> 명사형 어미가 남아 있지 않은지 확인
-> git diff --check를 통과하는지 확인
```

---

## 11. 완료 / 실패 / 미검증 처리 기준

```yaml
완료
-> 대상 문서의 공통 양식 정리와 검증이 완료됨

실패
-> 대상 경로를 확인할 수 없음
-> 파일명 변경 또는 참조 갱신 중 충돌이 발생함

미검증
-> 일부 문서를 열람하지 못함
-> 날짜 / 상태 / 브랜치의 실제 값을 확인하지 못함
-> 내부 링크 전체 검증을 수행하지 못함
```

## 12. 기존 Prompt와 역할 경계

```yaml
Document Format Normalization Prompt
-> 문서군의 파일명 / 상단 메타 / 문체 / 공백 양식 정리

Document Set Audit Prompt
-> 문서군의 역할, 구조, 용어, 경로, 상태값, 운용 가능성 감사

Document Writing Prompt
-> 문서 카테고리별 내용 작성 / 보완
```
