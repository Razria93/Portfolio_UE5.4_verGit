# CPlayerCharacter 이동 코어 및 기본 로코모션 AnimBP 구현

## 제목

✨ feat: 이동 코어 및 기본 로코모션 AnimBP 구현 (#6, #7)

## 요약

- 이 PR은 **캐릭터 기본 이동 시스템**(WASD + 점프)을 구현하고, **기본 로코모션 AnimBP**를 구성함

- 또한 **Mannequin 애니메이션을 Quinn 스켈레톤에 직접 적용할 때 발생하던 포즈 왜곡** 문제를 **리타겟 파이프라인(IK Rig/Retargeter)**로 해결함

---

## 완료 항목

### 1. 이동 / 점프 로직

- 이동 로직 구현
    
    - `CPlayerController`가 이동 축 입력을 수신
        
    - `CPlayerCharacter`의 이동 처리 함수로 전달
        
    - `CharacterMovementComponent`의 `OnMoveForward`, `OnMoveRight`로 위임
        
    - `CharacterMovementComponent`에서 입력 정규화/검증 후 이동 적용
        
- 점프 구현
    
    - `CPlayerController`가 점프 액션 입력을 수신
        
    - `CPlayerCharacter`의 점프 핸들러를 `Jump` / `StopJumping`에 바인딩
        
    - `CPlayerCharacter`는 `ACharacter` 점프 API를 호출하고, 공중 이동은 `CharacterMovementComponent`가 처리
        

---

### 2. 로코모션 AnimBP

- Quinn 기준 임시 무장 해제(Unarmed) 애니메이션 선정
    
    - Idle / Walk / Run
        
    - Jump Start / Jump Loop / Jump End
        
- 지상 이동을 위한 속도 기반 로코모션 **BlendSpace** 구성
    
- **AnimBP 구현**
    
    - 지상 상태 머신: Idle / Move
        
    - 공중 상태: Jump Start → Jump Loop → Jump End → Idle/Move 복귀
        
    - `Speed`로 BlendSpace 구동, `bIsInAir`로 지상/공중 전환
        
- `UCMovementComponent`에서 AnimInstance로 전달/갱신
    
    - 현재 `Speed`, `Direction`
        
    - `IsFalling`
        

---

### 3. 애니메이션 리타겟 수정 (Mannequin → Quinn)

- 이슈: #7
    
- Mannequin 애니메이션을 Quinn에 직접 적용할 때 발생하는 **포즈 왜곡 문제**를 확인하고 수정
    
- UE5.0 프로젝트에서 필요한 Mannequin 기반 에셋만 최소 단위로 가져옴
    
    - `SK_Mannequin`, `SK_Mannequin_Skeleton`, `SK_Mannequin_PhysicsAsset`
        
- 기본 **IK Rig + IK Retargeter** 구성
    
    - `IK_AutoGeneratedSource` (Mannequin)
        
    - `IK_AutoGeneratedTarget` (Quinn)
        
    - `RTG_AutoGenerated` (Retargeter)
        
- 로코모션 애니메이션을 Quinn으로 리타겟 후, 깨지던 애니메이션을 교체

## 테스트 방법

1. 프로젝트 실행 후 TestRoom 레벨에서 플레이
    
2. **WASD**로 이동
    
3. **Space**로 점프하고 착지 동작 확인
    
4. 아래 항목 확인
    
    - 속도 기반 로코모션(Idle ↔ Walk ↔ Run)이 자연스럽게 블렌딩되는지
        
    - 점프가 정상 동작하는지
        
        - 입력 시 Jump Start → Jump Loop → Jump End 흐름이 동작
            
        - 착지 후 Idle/Walk/Run으로 자연스럽게 복귀(스냅 없음)
            
    - 팔/다리 포즈 왜곡이 발생하지 않는지
        
    - 이동/카메라 입력 감각이 일관적인지

## 노트

- 이동/애니메이션 흐름 책임이 명확히 분리됨
    
    - **Controller**: 플레이어 입력 수신 후 캐릭터로 전달
        
    - **Character**: 이동/점프 의도 결정 후 MovementComponent로 위임
        
    - **MovementComponent**: 이동/점프 가능 여부 판단 및 실제 이동 적용
        
    - **AnimInstance**: `Speed`, `Direction`, `bIsInAir` 기반으로 로코모션/점프 상태 구동
        
- 리타겟 파이프라인이 안정화되어, 이후 전투/기타 애니메이션에도 동일한 방식으로 재사용 예정
