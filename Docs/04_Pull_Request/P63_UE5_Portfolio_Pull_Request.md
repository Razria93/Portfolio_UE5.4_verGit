## 요약

### Documentation

이번 PR은 새 캐릭터·무기·환경을 기존 전투 프로젝트에 통합한 작업을, 코드 리팩터링 목록이 아니라 문제와 해결 과정으로 설명할 수 있도록 문서화한다. 리타게팅과 에셋 교체를 중심에 두고, 무기 규격 차이를 해결하기 위한 소켓·피벗·계층·수명 변경을 연결한다.

작업 내역은 무엇을 바꿨는지, 이슈 분석은 왜 그 방법을 선택했는지, 설계 문서는 현재 책임과 실행 계약을 설명하도록 분리했다. 각 주장에 원래 작업 커밋, 최종 재구성 커밋, 세션과 현재 구현·사용자 확인 근거를 연결하고, 당시 제안과 실제 적용·검증을 구분했다.

확인하지 못한 사실을 문서의 빈칸을 채우기 위해 추정하지 않았다. 리타게팅 설정과 자체 참조 조회 도구 사용은 사용자 자료로 확인하고, 환경 충돌·조명은 합의한 작업 내역 수준으로 제한했다. 기존 PR #121의 짧은 영문 요약을 대체할 본문도 해당 구현 시점에 맞춰 작성했다.

- **근거 목록**: 코드 존재·당시 기록·사용자 확인·검증 한계를 구분하고 출처를 연결한다.

## 변경 배경

기존 PR #121은 LFS 정규화와 Weapon Presentation 리팩터링을 짧게 나열했지만, 가장 큰 작업인 새 캐릭터·애니메이션 세트 통합과 그 과정에서 드러난 문제를 충분히 설명하지 못했다.

또한 작업이 여러 세션과 staging/final 재구성 이력에 나뉘어 있어, 커밋 목록만으로는 같은 변경을 중복 집계하거나 당시 제안을 최종 구현으로 오해하기 쉬웠다. 소스만으로는 리타게팅 설정과 에셋 정리 판단도 설명하기 어려웠다.

따라서 기존 자료를 근거별로 대조하고, 전체 작업과 개별 문제 해결 과정, 현재 설계 계약을 구분해서 조회할 수 있도록 정리했다.

## 주요 변경

### 1. 에셋 통합의 작업 범위와 이력 정리

- **결과**: 커밋별 파일 수를 더해 고유 에셋 수로 주장하지 않고, 에셋 제작자의 기여와 본인의 통합·설정·C++ 구현을 구분할 수 있다.

### 2. 문제 해결 보고서와 설계 문서의 역할 분리

- **왜**: 기존 S39의 구조 설명만으로는 새 에셋 때문에 어떤 문제가 발생했고 왜 해당 설계를 택했는지 드러나지 않았다.

### 3. 세션·사용자 화면을 통한 주장 보완
