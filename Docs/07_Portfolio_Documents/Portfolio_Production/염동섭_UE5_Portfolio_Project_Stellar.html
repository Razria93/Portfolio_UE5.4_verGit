04 · TARGETING

Targeting

카메라 기준 후보 평가로 전투 대상을 선택하고, 선택 상태를 카메라·이동·표시에 적용

Target LockInput
to Camera

핵심 기준: 대상 선택 정책은 후보 평가와 상태 변경만 담당하며, 카메라·이동·표시는 동일한 전투 대상 변경 이벤트를 구독해 각자의 방식으로 반영합니다.

Player Target Lock 동작 흐름

01. 선택 요청

중앙 클릭으로 선택·해제하고, 휠 입력으로 화면 좌우의 인접 대상을 전환합니다.

02. 후보 평가

카메라 ViewPoint 기준 생존·거리·시야각을 확인하고, 각도와 거리 점수로 대상을 비교합니다.

03. 전투 대상 갱신

대상 참조와 Revision을 저장하고, 교체·사망·파괴 시 변경 이벤트를 발행합니다.

04. Lock 적용

카메라 추적·이동 회전 모드·대상 마커가 변경 이벤트를 구독해 각각 반영합니다.

07 · DODGE INTERVENTION

Dodge Intervention

회피 요청은 현재 실행과의 관계·개입 허용 조건을 통과할 때만 적용

핵심 기준: 회피 요청은 현재 실행을 무조건 덮어쓰지 않습니다. 새 요청의 Want와 현재 Action·Reaction의 Allow가 모두 성립할 때만 시작하거나 개입합니다.

회피 실행과 상태 전환

01. Dodge 요청

입력은 직접 실행하지 않고 `EActionType::Dodge` 후보를 생성합니다.

02. 실행 관계 판단

현재 실행과의 관계를 판정해 Start·Intervene·Reject를 결정합니다.

03. Guard 상태 정리

Guard가 활성이라면 `ClearGuardState`를 먼저 적용합니다.

04. 결과 적용

수락된 결과만 Dodge로 적용하고 실행 결과를 기록합니다.

런타임 검증

01. Idle → Dodge

Active ActionNoneIncoming ActionDodgeDecisionAcceptRelationshipNoneOverlay HandlingNoneApply ModeStart

판정 의미실행 중인 Action 또는 Reaction이 없으면 Dodge 요청은 즉시 수락되어 새 실행을 시작합니다.

02. Active → Dodge

Active ActionAttack_01Incoming ActionDodgeDecisionAcceptRelationshipExclusiveOverlay HandlingNoneApply ModeIntervene

판정 의미현재 실행과의 관계가 허용되면 Dodge가 기존 실행에 개입해 전환을 요청합니다.

03. Guard → Dodge

Active ActionGuardIncoming ActionDodgeDecisionAcceptRelationshipExclusiveOverlay HandlingClearGuardStateApply ModeIntervene

판정 의미Guard 상태를 먼저 정리한 뒤 Dodge로 전환해 방어 상태가 다음 실행에 남지 않게 합니다.

설계 판단 | 개입 정책의 책임 분리

기존 위험Notify가 정책과 timing을 함께 가지면 montage 경계에서 판단 경로가 흔들릴 수 있습니다.
분리한 책임incoming의 Want와 active의 Allow는 Action·Reaction Data가, Notify는 Allow window timing만 담당합니다.
검증 기준요청 결과의 Decision·ApplyMode·RejectReason을 남겨 수용·거절의 이유를 추적합니다.
